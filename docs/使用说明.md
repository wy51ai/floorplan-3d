# 筑家 · 装修规划与交底

## 从一个真实房间开始

1. 打开本地页面，在「户型」中选择 **「上传户型图识别」**。上传平面图后，系统自动识别墙体、房间和门窗，叠加预览。若识别到外围尺寸/比例线，则以该范围为界，线外内容一律忽略；图面指南针只识别东南西北（如北朝上），写入项目北向。核对比例（可读出尺寸标注，或在预览图上选两点并用已知长度校准），确认后生成可编辑户型；底图会去掉无关界面元素并保留指南针。不区分承重/可拆，门窗类型需对照精调。
2. 若暂无图纸，可用「建立空白户型」再添加矩形房间；或仅上传底图手工描墙。与相邻房间共用的墙需手工调整，避免重复。
3. 点击墙段或房间编辑尺寸；窗、平开门、推拉门可从构件列表编辑。墙体性质初始为待确认，核实后记录依据。门窗不会自动切割墙体，需调整墙段给洞口留空。
4. 在「布置」中拖入家具。新增或选中家具会自动切换到布置属性，保留原来的旋转、缩放和三维编辑。
5. 在「设备点位」添加真实生活需求，选择设备需要的预留类型。填写型号或安装资料，点击「补齐关联点位草稿」，逐个确认位置、距完成地面的高度、墙面、回路和施工备注。也可以在图上直接放置点位。
6. 打开「检查」，分别处理冲突、漏项和待复核项，点击「定位并处理」跳转到对象。初始示例户型未经现场复核，出现很多待确认项是正常的。
7. 在「交底」冻结一个版本，填写变更说明。按房间、工种预览并打印为 PDF，或导出可独立打开的 HTML。图上 P 编号对应清单行。
8. 施工中新增问题，关联对象编号，填写责任人、整改结果并添加现场照片。复核后关闭。点位也可标记为已确认、已施工、已验收；修改已施工点位的位置会重新转为待确认。
9. 定期导出完整 JSON 备份。恢复时验证文件，失败不会改变当前方案；成功导入可撤销。交底 HTML 不具备恢复项目的能力。

## 保存与版本

数据保存在当前浏览器、当前访问地址对应的 localStorage 中。换浏览器、换端口、从 localhost 改用 127.0.0.1，可能看到不同的数据。跨设备请导出并导入完整 JSON。

底图和现场照片上传后会缩放压缩，降低存储占用。最多保留 12 个交底版本，每个版本保存当时完整数据但不递归包含旧版本。版本、照片较多时浏览器存储可能不足；页面会明确显示「未持久保存」，此时请立即导出备份。刷新前请确认保存状态。

旧版方案 JSON 可导入，沿用原项目示例户型补全旧文件没有保存的建筑数据；不会把它标记为你家实测户型。

## 当前边界

- 墙段使用轴对齐矩形，房间支持不自交的多边形。支持本地光栅户型图识别（横竖墙为主）；暂不支持斜墙、弧墙、CAD/DWG 导入和墙体自动拼接。识别结果需人工核对。
- 层高减去地面完成层得到用于三维和高度检查的净高；墙面完成层厚度只作记录，没有自动偏移墙体或扣减房间轮廓。
- 通用电源等预留模板可编辑，安装条件以选定设备和现场方案为准。系统不计算电路载荷、线径，也不自动设计给排水线路。
- 当前几何检查包括家具与墙体、门开启平面扇区、门窗洞口与墙段。门扇与家具为待复核提示，不是确定的三维碰撞结论。尚未覆盖所有家具间冲突、通道宽度、设备检修空间。
- 控制关系用于设计记录；没有接入米家或其他真实设备。三维彩色球和标签表示点位位置与高度。
- 交底图为示意，禁止通过打印比例量尺；以清单数值及现场实测为准。不是专业施工 CAD 图。
- Three.js 仍通过原项目 jsDelivr CDN 加载；首次使用三维需要联网。二维编辑、模型检查及交底生成功能使用本地脚本。
- 三维「日照」滑条按户型北向（东南西北）模拟北半球日照：上午偏东、正午偏南、下午偏西；夜景模式单独开关。

## 开发与验证

无需编译，启动方式保持不变：

```bash
python3 -m http.server 8000 --bind 127.0.0.1
```

首次使用前安装依赖（含本地中文 OCR 模型）：

```bash
npm install
```

开发测试：

```bash
npm test
npm run test:e2e
```

浏览器测试在 macOS 优先使用已安装的 Google Chrome；其他环境先执行 `npx playwright install chromium`。测试使用独立浏览器上下文，不会改动使用者当前浏览器的方案。

代码结构：`index.html` 保留原二维/三维编辑器；`js/project-model.js` 负责项目迁移、校验与规则；`js/project-ui.js` 负责工作区、导入导出与交底；`js/recognition-*.js` 负责户型图识别与预览；`project.css` 为新增样式。

### 编辑家具库与图片识别

- 左侧家具库的「编辑家具库」可修改或删除条目，「＋ 新增」可手动建立家具。分类、模型类型、颜色和长宽高均可编辑，尺寸单位为毫米；长对应正面水平宽度，宽对应前后进深。
- 新增或编辑时可上传同一件家具的 1–8 张照片或尺寸图（PNG / JPEG / WebP，每张最大 10 MB），补充已知尺寸后点击「AI 识别长宽高」。图片会经过缩放压缩并发送到所配置的服务；原始图片不保存在家具库中。
- 识别优先读取标注，缺乏比例参照时只能估算。界面会展示依据，无法判断的尺寸留空，核对或补充后再保存。3D 使用所选类型的近似模型，并按保存的高度缩放。
- 顶栏「AI 接口设置」是独立的公共设置，家具识别和「AI 帮你装」共用服务地址、密钥和模型。图片识别需选择支持图像输入的模型；普通文本连接测试成功不代表支持图片。
- 家具库保存在当前浏览器本机，与项目文件分开。刷新后保留；修改或删除条目不会改变已摆放的家具。已摆放家具的高度随项目导出、方案槽和撤销记录保存。

### 两套 AI 接口配置

「AI 接口设置」分别保存 OpenAI、DeepSeek 两套地址、密钥、模型与模型列表。「当前使用的接口」选择哪一套，后续 AI 请求就使用哪一套。切换会先保存当前表单，再载入另一套；首次切换到未配置的服务商时密钥为空，需要自行填写。清除当前密钥不会影响另一套。原有单套配置会自动保留到其对应服务商，当前选择也会在刷新后保留。

### AI 尺寸模型

家具编辑页的「AI 识别并建模」会要求当前支持图片输入的模型综合照片，返回尺寸、依据与基础部件模型。模型由最多 48 个长方体、竖直圆柱或椭球构成，描述部件的位置、比例与颜色，不执行 AI 返回的代码。

识别后可在家具信息中旋转预览、查看部件和依据；调整总长宽高会同步调整模型比例。模型和识别依据随家具库保存，摆入户型后随项目备份、方案槽、复制和撤销保留，2D 图例与 3D 场景均使用自定义模型。移除生成模型即可恢复内置类型。

这是供布置验证使用的近似尺寸模型，不含照片纹理，也不代表精确扫描。尺寸缺失时仅预览比例，需补齐毫米尺寸后保存。模型缺失或无效时会显示原因并保留有效识别尺寸。
